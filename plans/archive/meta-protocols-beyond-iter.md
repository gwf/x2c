# Meta-capable protocols beyond Iter

> Status: done - landed on `dev` 2026-09-24: the default-member rule as
> `7fd8c5dd`, delivery 1 as `186ed550`, deliveries 2-4 as `7a371fa6`.
> Delivery 4's prototypes are written after the generated families,
> because a `meta` prototype inside a `macro Unit` does not parse yet.

## Result

Compile-time code reaches Array, Map and Buffer operations, and the typed
container conversions, through `meta` declarations that sit beside the
operations, instead of through hand rows in `lib/lisp.x`. Marked
adoptions cover the members of a protocol; plain `meta` prototypes cover
the rest.

## Current behavior

Facts from source on `dev` at `5023c07c`, with probes run by
`builds/0/x2c --dump-conformance`:

- Track E marks an adoption with `meta protocol Iter(List);`. The mark
  must be on the original adoption in `lib/protocols.x`; a second
  adoption elsewhere is "conflicting adoption declarations".
  `_native_meta_rows` (`src/macros.x:535`) exposes the members whose
  status is `implmntd` only.
- There is no Array, Map or Buffer protocol. The candidates are those
  types' `Var(T)` and `Block(T)` adoptions (`lib/protocols.x:47-51`).
  - Var(Array): 12 implemented members; the hand rows it replaces are
    `Array_getindex` and `Array_setindex` (`lib/lisp.x:1781`).
  - Var(Map): 13 members; replaces `Map_getindex` and `Map_setindex`
    (`lib/lisp.x:1790`).
  - Block(Array): 7 members, all `base-default`, so the helper takes none;
    six hand rows (`Array_len`, `Array_truth`, `Array_capacity`,
    `Array_clear`, `Array_pop`, `Array_truncate`) wait on it.
  - Var(Buffer): `str`, `repr`, `truth` only; `Buffer.new` has no binding.
- Most of the archived phase 7 list is outside any protocol: the 16
  Buffer writers (`lib/buffer.x:101-270`), the 22 typed Array and Map
  conversions (`lib/typed-array.x`, `lib/typed-map.x`), and the
  `Var.block`, `Var.jsonbool` and `Var.regex*` converters.
- Lifetimes: `_native_meta_summary` (`src/macros.x:1758`) treats a
  returned handle as fresh. That is wrong for `write_str`/`write_repr`
  and the Buffer writers, which return their Buffer argument.
- Only the typed containers use custom class rows (11). Array, Map,
  Buffer, Block and Iter are built-in rows. So class registration
  matters only to delivery 4, which narrows the dependency
  [meta sequencing](meta-sequencing.md) assumed.

## Design

### Delivery 1: Var(Array) and Var(Map)

- `lib/protocols.x` marks `meta protocol Var(Array);` and
  `meta protocol Var(Map);`.
- `src/regions.x` gains `(summary 0 ((1 return)))` rows for
  `Array_write_str`, `Array_write_repr`, `Map_write_str` and
  `Map_write_repr`, which return their Buffer argument. These rows
  already exist for other returning-argument functions; the region
  analysis reads them before the inferred summary.
- Delete the four getindex/setindex hand rows and the `meta` markers on
  Array and Map prototypes that the marked adoption now covers. The Lisp
  aliases in `etc/lisp-values.xlisp` name the same C targets and stay.
- No compiler change, so it lands in one step.

### Delivery 2: default members (compiler capability, then Block)

- `_native_meta_rows` also accepts `base-default` members of a marked
  adoption, exposing the forwarding function the conformance already
  generates (`Array_len` and so on). This is a compiler capability: it
  lands and reaches `bootstrap/` first.
- Then `meta protocol Block(Array);` and delete the six hand rows.

### Delivery 3: Buffer as `meta` prototypes

Buffer's writers are ordinary methods, so they get `meta` prototypes
beside their definitions in `lib/buffer.x`, with `Buffer.new`. Writers
that take `const char *` get the same kind of adapter the archive plan
lists; `printf`-style variadic writers stay out. Each writer that returns
its Buffer gets the returning-argument region row.

### Delivery 4: typed conversions (after class registration)

The typed Array and Map `.var` and `Var.x` converters are generated by
`lib/array-generics.xmacro` and `lib/map-generics.xmacro`. The generator
emits a `meta` prototype for each, so the 22 conversions bind on first
use. `Var.block`, `Var.jsonbool` and the `Var.regex*` converters get
`meta` prototypes beside their definitions. This follows class
registration because linking and boxing the typed containers in the
compiler spends their rows.

Status: implemented 2026-09-24 with two changes. A family macro cannot
emit a `meta` prototype: a template parse rejects a hole declarator after
`meta`, and the marker would install on the template rather than on its
expansion. The 33 prototypes (`.var`, `Var.x`, and the `Array.x` and
`Map.x` packers that give a meta body a typed value) are literal after the
expansions in `lib/typed-array.x` and `lib/typed-map.x`, as the slicing
prototypes already are. `etc/runtime-objects.sh` no longer leaves out
row-reserving objects; the compiler's row count after startup is unchanged
(1 for `--version`, 2 after a translate). The typed and Regex targets bind
only once `lib/lisp.x` includes `regex.x`, `typed-array.x` and
`typed-map.x` beside `json.x`.

## Compatibility

- Compile-time names are unchanged: lowered calls bind the same C targets
  on first use instead of at session start, as track E already does.
- The generated C is unchanged by deliveries 1, 3 and 4. Delivery 2
  changes only the compiler's binding inventory.
- Book: the compile-time surface table in
  `docs/src/guide/meta-functions.md`.

## Implementation

Per delivery: make the change, then a probe that calls every newly bound
name from a `meta` body with and without explicit storage, compared with
the pre-change compiler's output; the `comptime-declines-local-address-*`
fixtures still pass; for delivery 1, a fixture where a meta body returns
`a.write_str(buffer)` and the region check attributes it to `buffer`.
Review the completed authored diff and fix what it finds, then
`tools/gate-state.py ensure agent-pr-check`.

## Design review

- Reuse: marked adoptions, lazy binding, region rows and adapters all
  exist; only delivery 2 changes the compiler, by one status rule.
- Deleted: 10 hand rows in `lib/lisp.x` and the redundant `meta` markers.
- Honest scope: marking protocols reaches only protocol members. The
  larger payoff is in deliveries 3 and 4, which use plain `meta`
  prototypes.
- Risk: the returning-argument region rows are required for correctness;
  delivery 1 must not land without them.
