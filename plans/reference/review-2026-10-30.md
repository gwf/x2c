## A. Code defects

### A-1. `Cpp.copy` shares each conditional group's `before` table (confirmed)

`src/cpp/cpp.x:85-96` copies `group.touched` but not `group.before`.
`src/cpp/conditions.x:97` installs `group.before` itself as the live table
when an undecided group closes. `src/collect/walk.x:441` copies the state at
every include that splits a segment, and `walk.x:612` hands that copy to the
segment's shadow compiler.

When an `#include` sits inside an undecided group, the main walk and the
segment shadow share one `before` Map. Whichever closes the group first
adopts the shared Map as its live table; its later `#define`/`#undef` lines
then write into the Map the other state adopts at its own `#endif`. The
shadow can see definitions from after its segment, and can decide a later
`#ifndef` arm differently from the unit's linear full parse. The
`Cpp.copy` doc comment ("independent", `cpp.x:31,84`) is false.

Scope: `--cpp` mode only (opt-in since PR #641). No `--cpp` fixture has an
include inside a conditional group. Symptom not run.
Repair: `if (group.before) group.before = group.before.copy();` in
`Cpp.copy`, plus one fixture.

### A-2. A forked REPL worker inherits the supervisor's catch frames (confirmed mechanism, consequence plausible)

`commands/repl/repl-worker.x:416-449` forks; the child runs `_worker_serve`.
`_worker_serve` (`:340-380`) catches only around `_worker_dispatch`. Startup
work before that (`Path.read_text(snapshot)`, `repl_program_restore`,
`repl_program_build_selected`, snapshot write) can raise. The fork happens
inside `repl_run`'s `try ok = _line(...)` (`commands/repl/repl.x:584-586`),
and the Error handler stack is thread state copied into the child; no
atfork reset exists (grep finds none).

A raise during child startup therefore lands in the supervisor's catch arm
inside the child. The child then runs the supervisor loop to EOF and its
defers (`repl.x:559-565`): `repl_worker_close` on the previous, live worker
(whose fds the child closed, so the quit send fails and `_worker_reap`
kills the process group), `save_history`, and `_artifact_remove` of the live
program directory and snapshot. The parent then reports "session unchanged"
and recovery has no snapshot.

Triggers: a missing snapshot after `$TMPDIR` cleanup (`<not-found>`), an
`io-fail` from `Path.temp_dir`/`write_text`, or a transform-time error that
raises `<malformed>` through `repl-program.x:541-545`.
Repair: wrap the whole child body in a catch-all that sends
`{status: failed}` and `_exit`s.

### A-3. `:reload` and `:load` duplicate manifest inputs (confirmed)

`commands/repl/repl-program.x:912-913` appends `request.inputs` (including
`<tmp>/dependency-N.a`) to `roots`, and `:949` stores the result as
`program.roots`. The ready frame echoes `program.roots` to the supervisor,
which sends them back as the roots of `:reload`/`:reset`/`:load`
(`repl.x:359-373`). The rebuild appends the new inputs again, so the root
list grows on every reload and two dependency archives reach a
`-force_load`/`--whole-archive` link. Link failure is plausible (duplicate
definitions), not run. Only the initial manifest build is tested.
Repair: keep user roots apart from manifest-derived inputs.

### A-4. Crash recovery is not recorded in the transcript (confirmed)

`repl.x:144-146` `_record` runs only for `:load`, `:reload`, `:reset`
(`:400-401`). `_recover` (`:173-181`) restarts a fresh session without a
boundary, so `:save` then `:replay` of a session that crashed between two
declarations of the same name fails with "redeclaration is disabled".
Contradicts `docs/src/guide/repl.md:197`.
Repair: `_record(client, ":reset")` after a successful recovery.

### A-5. Failed candidate builds leak `$TMPDIR/x2c-XXXXXX` (confirmed)

`repl-program.x:898` creates `program.directory`; every early
`return NULL` (`:906-956`) and the worker's failed frame
(`repl-worker.x:353-356`) leave it. `playground.py` and `terminal.py` do not
set `TMPDIR`, so failing-load tests leak into the real one.
Repair: remove the directory on every failure return; send it in the
failed frame.

### A-10. Host-symbol modes still run x2c macro expansion (confirmed)

`src/frontend.x:579-581` sets `cpp.cpp = Cpp.new({})` "because the host has
already expanded"; since the boundary change, any non-NULL `c.cpp` enables
`expand_macros` (`src/compiler/parsing/tokens.x:40`). So `--cpp-symbols`,

### A-11. `--cpp --no-cpp` leaves the prelude expanded (confirmed)

### A-12. `#if` evaluation disagrees with the C compile in corners (confirmed)

`src/cpp/conditions.x:316-319` evaluates a character constant as
`unsigned char`, while generated C compiles with `-fsigned-char`
(`src/toolchain.x:359`): `#if '\xff' < 0` is true for the C compiler and
false for x2c, which then hides the arm C takes. Multi-character constants
use the first byte only. Shift counts are masked with `& 63`
(`:241-242`), and `LONG_MIN / -1` is evaluated natively (`:246-247`, a
SIGFPE in the compiler on x86-64). Repair: sign-extend single characters;
leave the rest undecided.

### A-13. Macro arguments group commas inside `[]` and `{}` (confirmed, documented as C99)

`src/cpp/expand.x:276-279,321-339` treats brackets and braces as grouping
for argument commas; `docs/src/reference/language.md:4654` promises "C99's
rules". `COUNT((int[]){1, 2})` with a counting macro gives 2 in C and 1 in
x2c. Now that `--cpp` is for existing C, either document the deviation or
group only parentheses.
