# Three-word cons experiment

Measured on 2026-09-19 on the local macOS arm64 host, against base
`bbd78cc0` plus this experiment. These are one-run observations, not a
cross-machine benchmark or a comparison against a sidecar counter.

The input was all 88 hand-authored `src/*.x` and `lib/*.x` units, excluding
`lib/x2c.x`. The command was `clones --min-size 100`. Parsing executes macros;
size therefore measures expanded cons cells, not source lines.

| Measurement | Result |
| --- | ---: |
| Normalized cons occurrences | 2,239,335 |
| Distinct canonical cells | 505,478 |
| Cell storage, used | 12,131,472 bytes |
| Cell storage, allocated capacity | 12 MiB |
| Hash index capacity | 8 MiB |
| Size-array capacity | 4 MiB |
| Counter share of allocated cell storage | 4 MiB |
| Whole-process peak resident memory | 199.70 MiB |
| End-to-end wall time | 5.17 seconds |
| Parse CPU time | 4.15 seconds |
| Normalization and binding-verification CPU time | 0.75 seconds |
| Located repeated candidate groups, before report suppression | 1,270 |
| Unlocated qualifying root occurrences | 2,095 |

Peak resident memory was read from Python `resource.getrusage(RUSAGE_CHILDREN)`
after the single tool subprocess. It includes parsing, atom keys, provenance,
binding signatures, report work, and native arrays. The 24 MiB native-array
capacity is not the total cost. The measured counter overhead is relative to
the same capacity of two-word cells, not a measured alternative implementation.

## Source-checked examples

A second run with `--min-size 512` made the larger matches easy to inspect.

- A 1,467-cell match joins `_integer_raw` in `lib/typed-map.x:233` and
  `lib/varops.x:96`. Both are already generated by
  `$integer.raw(_integer_raw)`. This is a correct match and an existing
  abstraction, not newly discovered handwritten duplication.
- A 528-cell match joins `Compiler.convert_compound_literal` near
  `src/expressions.x:3733` and `_convert_composite` near line 3566. Both
  construct the same nested typed zero-pointer dereference template under
  different local names. This is a concrete candidate for investigating a
  shared constructor. The experiment does not establish whether extracting
  it improves the compiler or preserves all surrounding responsibilities.
- The 100-cell run groups the child-rewrite machinery in
  `Ast.rewrite_children`, `_children`, and related walkers. Source inspection
  shows uses of the existing `$ast.rewrite_children` macro. Again, expansion
  repetition can be evidence of successful reuse.

Several high-frequency results come from `$lisp.bind` and list-literal
construction. Keeping source provenance and separating shared-macro expansion
from handwritten duplication would improve the next investigation. No source
simplification was performed as part of this experiment.

## Validation and limits

The optional `python3 tests/test-clones.py` checks alpha-renamed bodies,
fragment-relative binding correspondence, repeated-versus-distinct locals,
literal/operator/callee differences, static identity across units, block-scope extern identities, local function
pointers, deterministic
input order, histogram accounting, nested suppression, and bounded site output.
The existing Graph suite is also run separately from the repository gate.

Basic structural interning is expected linear work. Binding verification
rescans qualifying subtrees and can be quadratic on deeply nested inputs;
source fallback and candidate suppression add separate work. This prototype
therefore does not claim that the entire command has a linear worst-case
bound. Public names assume consistent linkage, and macro-generated names can
prevent otherwise useful matches. Near-match similarity scoring is not yet
implemented.
